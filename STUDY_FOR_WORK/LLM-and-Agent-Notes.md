# 第一部分：基础概念

## LLM 是什么

LLM（Large Language Model，大语言模型）是一个超大的神经网络（基于 Transformer 架构），在海量文本上训练而成。

**它唯一的工作**：输入一段文本，预测下一个 token 是什么。然后把预测结果接回去，再预测下一个——循环往复，即**自回归生成**。

「大」指三样东西：参数量（几十亿～上万亿）、训练数据量、算力。代表：GPT、Claude、Gemini、DeepSeek、Qwen、Llama。

必须记住的特性：

| 特性 | 说明 | 后果 |
| --- | --- | --- |
| **无状态** | 每次调用相互独立，不记得上一句 | 「记忆」全靠把历史重新塞进上下文 |
| **知识冻结** | 训练完权重固定，不再学新知识 | 新发生的事它不知道 → 需要 RAG |
| **只会输出文本** | 不能真的点按钮、查库、发邮件 | 想让它「做事」必须外接工具 → Function Calling |
| **能力涌现** | 训练目标只是预测下一个词 | 规模够大后自己会翻译、写码、推理 |

**生命周期三阶段**：预训练（学语言与世界知识）→ SFT 指令微调（学会听指令）→ 对齐 RLHF/DPO（学会说人话、守规矩）。

---

## NLP 是什么

NLP（自然语言处理）是人工智能的分支，研究如何让计算机理解、处理和生成人类语言。

**难点**：语言是离散的、有歧义的、依赖上下文的——同一个「苹果」，可以是水果也可以是公司。

---

## 语言模型

**定义**：给一个词序列打分，衡量它「像不像人话」。两种等价表述：

$$P(w_1, w_2, \dots, w_n) \quad \text{或} \quad P(w_t \mid w_1, \dots, w_{t-1})$$

任何语言模型都能干三件事：**给句子打分**（判断是否通顺）、**预测下一个词**、**生成文本**。

**关键定义**：给定一个词表 V（比如 3 个词：{我, 吃, 饭}），语言模型要能给出词表上所有词的完整概率分布，且总和为 1。

**算例**

设 $P(\text{吃} \mid \text{我}) = 0.6$，$P(\text{睡} \mid \text{我}) = 0.3$，$P(\text{饭} \mid \text{我}) = 0.1$（和为 1）。那么句子「我 吃 饭」的概率就是逐步累乘：

$$P(\text{我 吃 饭}) = P(\text{我}) \times P(\text{吃} \mid \text{我}) \times P(\text{饭} \mid \text{我 吃})$$

---

## n-gram

NLP 里最基础的语言模型之一，思想非常朴素：**用前 n-1 个词预测下一个词**。

它不做任何「理解」，纯粹靠统计——在大量语料里数，哪个词跟在某个词序列后面出现的次数最多。

> 语言模型的演进线：n-gram（数频次）→ 神经网络 LM → word2vec → RNN/LSTM → Transformer/GPT

# 第二部分：序列建模的演进

## RNN（循环神经网络）

> 深度学习时代处理序列数据的经典网络——2017 年 Transformer 出现之前，它是 NLP 的主力。

**核心思想**：给网络装上「记忆」，一步一步读序列，每一步都把读到的内容融进一个记忆向量里。

**三个要点**

| 要点 | 说明 |
| --- | --- |
| 循环结构 | 每个时间步读一个词，更新隐藏状态 h，h 就是网络的「记忆」 |
| 共享权重 | 所有时间步用同一套 W——序列可任意长，参数量却不随长度增长 |
| 历史压缩 | 整句信息被逐步「压缩」进一个固定长度的向量里 |

**致命弱点**

1. **长距离依赖丢失**：开头词的信息按步衰减，长句传到结尾早就「忘」了。
2. **梯度消失 / 爆炸**：反向传播要沿时间步连乘 W，$0.8^{10} \approx 0.1$，梯度同样指数级衰减，训练不动。
3. **无法并行**：必须算完 $h_{t-1}$ 才能算 $h_t$，GPU 的并行能力用不上，训练慢。

**后续的补救与终结**

- **LSTM / GRU（1997 / 2014）**：给单元加了「门控」——遗忘门决定丢什么、输入门决定记什么，缓解了衰减问题，但要背的公式也多了。
- **Transformer（2017）**：干脆放弃「逐词压缩」，让每个词直接注意到句中所有词——距离为 1，信息不衰减，且全并行。这正是《大模型原理与架构》第 1 章讲「序列建模基础」、第 2 章讲注意力的动机所在。

---

## LSTM（长短期记忆网络）

1997 年 Hochreiter 和 Schmidhuber 提出的 RNN 改进版。

**核心思想**：给 RNN 加一条独立的「记忆传送带」（细胞状态 C），再用三个「门」控制信息进出——这样重要信息可以几乎无损地穿过很多时间步。

---

## CNN（卷积神经网络）

专门处理具有网格结构数据的神经网络——最典型的是图像（像素排成 2D 网格），也用于音频、时序。

**核心思想**：用一个小窗口（卷积核）在整张图上滑动扫描，局部提取特征并共享参数。

---

## MoE（Mixture of Experts，混合专家）

当前大模型的主流架构之一（DeepSeek-V3、Qwen、Mixtral 都用它）。

**核心思想**：把一个大 FFN 拆成很多个「专家」小网络，每次输入只激活其中少数几个，其余不动——用极小的计算量换取极大的参数量。

---

## Multi-Head Attention（多头注意力）

Transformer 的核心组件。

**核心思想**：把注意力机制并行地跑很多遍（很多「头」），每一遍用不同的投影矩阵，让不同的头从不同角度关注序列——然后拼接起来，一次拿到多种视角的信息。

---

# 第三部分：序列标注的经典方法

## 隐马尔可夫模型 HMM

**定义**：给一个观测序列，推断背后隐藏的状态序列。典型场景——**词性标注**：你看到的词是「观测」，词性是「隐藏状态」。

**两个核心假设**（这就是「隐」和「马尔可夫」的含义）

1. **马尔可夫假设**：当前状态只依赖前一状态
   $$P(z_t \mid z_1, \dots, z_{t-1}) = P(z_t \mid z_{t-1})$$
2. **观测独立假设**：当前观测只依赖当前状态
   $$P(w_t \mid z_1, \dots, z_T, w_1, \dots, w_T) = P(w_t \mid z_t)$$

**模型由三组参数构成**

| 参数 | 含义 | 例子 |
| --- | --- | --- |
| 初始概率 $\pi$ | 第一个词是各词性的概率 | — |
| 转移概率 A | 词性之间的转移 | $P(\text{动词} \mid \text{名词})$：名词后接动词很常见 |
| 发射概率 B | 某词性生成某词的概率 | $P(\text{"吃"} \mid \text{动词})$ |

**算例**：句子「我 爱 学习」，词表 {我, 爱, 学习}，标签集 {名词, 动词}。

已知条件：

- $P(\text{名词} \mid \text{名词}) = 0.4$
- $P(\text{动词} \mid \text{名词}) = 0.6$
- $P(\text{"爱"} \mid \text{动词}) = 0.5$
- $P(\text{"学习"} \mid \text{动词}) = 0.7$，$P(\text{"学习"} \mid \text{名词}) = 0.3$

那么「名词 → 动词 → 动词」这条路径的得分是（乘起来）：

$$\text{score} = P(\text{名词}) \times P(\text{"我"} \mid \text{名词}) \times P(\text{动词} \mid \text{名词}) \times P(\text{"爱"} \mid \text{动词}) \times P(\text{动词} \mid \text{动词}) \times P(\text{"学习"} \mid \text{动词})$$

**最优路径用 Viterbi 算法求**（动态规划，避免穷举所有 $2^3 = 8$ 条路径）。

**三大经典问题**：评估（前向算法）、解码（Viterbi）、训练（Baum-Welch，即 EM 算法）。

**致命缺陷**：观测独立假设太强了——它假设「词」只由自己的词性决定，因此同一个词的所有邻居信息都看不到。

> 「bank」在「river bank」（河岸）和「bank account」（银行账户）里词性完全不同，HMM 无法区分，因为「bank」本身没变。

---

## 条件随机场 CRF

**定义**：CRF 就是为解决 HMM 的缺陷而生的。它直接建模条件概率 $P(\text{标签序列} \mid \text{观测序列})$，不关心词是怎么生成的。

$$\text{score}(y \mid x) = \sum_t \left[ \sum_k \lambda_k f_k(y_t, y_{t-1}, x, t) \right]$$

$$P(y \mid x) = \frac{\exp(\text{score}(y \mid x))}{\sum_{y'} \exp(\text{score}(y' \mid x))}$$

**关键在于特征函数 $f_k$** ——它可以看任意信息：

- 当前词本身（「bank」是动词吗）
- 前后词的词性（**HMM 做不到！**）
- 当前词是否大写、是否含数字、是否在词典里
- 位置信息

**算例**：判断「river bank」里的「bank」，CRF 的特征可以写成：

| 特征 | 权重 $\lambda$ |
| --- | --- |
| 前一个词是「river」 | +3.0 |
| 后一个词是「the」 | +1.0 |
| 当前词小写 | +0.5 |
| 当前词出现在金融词典 | −2.0 |

总分 $= 3.0 + 1.0 + 0.5 - 2.0 = 2.5$ → 正数，倾向标为「名词（河岸）」。

如果换成「bank account」，「account」这个特征会把分数推向「银行」的标签——**HMM 完全做不到这一点**。

**总结**

| | HMM | CRF |
| --- | --- | --- |
| 类型 | 生成式（建模 $P(x, y)$） | 判别式（建模 $P(y \mid x)$） |
| 前提 | 需要假设观测独立 | 特征灵活，不计生成过程 |
| 表现 | — | 序列标注上几乎全面优于 HMM |

CRF 曾是实体识别、分词、词性标注的 SOTA。

---

## 知识框架：两条演进线

前面这些模型连成了一条完整的演进线：

**语言模型这一条线：从「打分」到「生成」**

```
n-gram（数频次）→ 神经网络 LM → word2vec → RNN/LSTM → Transformer/GPT
```

**序列标注这一条线：从「生成式」到「判别式」到「预训练」**

```
HMM → CRF → BiLSTM-CRF → BERT-CRF → 大模型直接生成标签
```

> ⚠️ 有趣的是，今天的趋势是**回归统一**：HMM 那个「隐藏状态」的思想，在 Transformer 里以「隐层表示」的形式复活了；而 CRF 层至今仍被加在 BERT 之后做实体识别（BERT-CRF 是工业界标配）。
>
> 经典方法并没有消失，它们成了新架构里的组件。

# 第四部分：Agent

## Agent 是什么

让模型**自己决定下一步做什么**的系统，而不是一问一答。

一句话原理：**LLM 做决策，工具做执行，上下文做记忆，循环做控制。**

> Agent 的「智能」来自模型，Agent 的「能干活」来自工程。

---

## Function Calling（函数调用 / 工具调用）

让 LLM 长出「手脚」的机制。解决的问题是：模型只会输出文本，没法真的执行动作。

**做法**：事先用 JSON Schema 把工具描述给模型，模型不直接执行，而是输出一个结构化的「调用意图」，由**你的程序**去真执行。

```text
1. 声明工具（JSON Schema）
   {
     "name": "get_weather",
     "description": "查询指定城市的天气",
     "parameters": {
       "type": "object",
       "properties": { "city": { "type": "string" } },
       "required": ["city"]
     }
   }

2. 用户问「上海今天热吗」
3. 模型输出（不瞎编，而是给出调用意图）：
   { "name": "get_weather", "arguments": { "city": "上海" } }
4. 你的代码解析意图 → 真的去调天气 API → 拿到「28°C 晴」
5. 把结果作为一条消息塞回上下文
6. 模型基于结果生成最终回答
```

> ⚠️ **最容易被误解的一点：模型本身不执行任何东西。**
> 它只负责「决定调哪个工具、传什么参数」；真正的执行永远是你的程序在做。
> 而且模型是被专门训练过输出这种结构化格式的 —— 所以它不是提示词技巧，而是**模型本身的能力**。

**它是 Agent 的地基：没有 Function Calling，Agent 就只能聊天，不能干活。**

---

## Agent 运行原理

### 核心机制

```text
state = 任务 + 系统提示
while not done and not timeout:
    output = LLM(state)            # 思考：决定下一步
    if output 是工具调用:
        result = 执行工具(output)   # 行动
        state += (output, result)  # 观察：写回上下文
    else:
        done = True                # 直接回答，退出循环
return output
```

这就是 **ReAct** 范式。不管 LangGraph、AutoGen 还是 OpenHands，外层包装多少抽象，**内核都是这个循环**。

### 几个关键机制

| 机制 | 说明 |
| --- | --- |
| **决策** | 靠 Function Calling。模型被训练过输出结构化调用意图（函数名 + 参数 JSON），不是外挂 |
| **记忆** | LLM 无状态，**一切记忆都靠重新塞进上下文**。短期 = 对话历史（要截断/摘要）；长期 = 外部存储（向量库/文件/数据库），检索回来再注入 |
| **规划** | 两种做法：**显式**（先让模型列 plan 再逐步执行）、**隐式**（每轮现场决定下一步） |
| **多智能体** | 把这个循环复制多份，再加一层消息传递/调度层 |
| **上下文管理** | ⚠️ **真瓶颈**。窗口有限、工具返回可能很长，所以要裁剪、摘要、外部化（中间结果写文件，上下文只留指针） |
| **控制流** | 纯工程：终止条件、最大步数、重试、超时、沙箱、人工确认点。**这才是能不能上生产的分水岭** |

---

## 优化手段：按成本从低到高

| 顺序 | 手段 | 备注 |
| --- | --- | --- |
| 1 | 改 prompt 和上下文组织 | 最便宜 |
| 2 | 改**工具设计**（名字、描述、参数） | 很多「模型不行」其实是工具描述写太烂 |
| 3 | 改控制流（加反思、加校验、拆步骤） | |
| 4 | 加 RAG | 模型不知道的，别硬让它记 |
| 5 | 调参数（temperature、最大步数） | |
| 6 | 换模型（更大 / 更小 / 更专） | |
| 7 | 微调 SFT / LoRA | **这才是动模型权重**，通常最后才用 |
| 8 | 蒸馏 | **成本优化**，不是效果优化 |

> ⚠️ 注意区分：招聘里说的「根据大模型效果优化」**不是「用大模型训练小模型」**（那是知识蒸馏，属于成本优化）。
> 这里指的是**评测驱动的系统迭代**，微调只是其中可选的一环。

# 第五部分：求职视角

## 招聘要求拆解

原话：**「独立 PE、独立搭建 Agent，根据大模型效果进行优化」**

这三个短语不是一件事，是**同一份工作的三个层次**：

| 层次 | 要求 | 本质能力 | 打比方 |
| --- | --- | --- | --- |
| 底层 | 独立 PE | 把业务需求翻译成模型能执行的指令 | 会写菜谱 |
| 中间层 | 独立搭建 Agent | 系统工程：架构、状态、工具、控制流 | 能把厨房搭起来 |
| 上层 | 根据大模型效果优化 | 评测驱动的迭代闭环 | 能吃出哪道菜差了、知道该改哪 |

### 1. 独立 PE（Prompt Engineering，提示词工程）

「独立」是关键——不是改别人写好的 prompt，而是从零把需求翻译成指令。

- **结构化写提示**：角色设定 / 任务描述 / 约束条件 / 输出格式 / 少样本示例
- **常用技巧**：CoT（思维链）、few-shot、ReAct、self-consistency、结构化输出（JSON Schema）
- **版本管理**：改了什么、哪个版本效果好，要可追溯、可对照（A/B）

### 2. 独立搭建 Agent

- 重点是**从 0 到 1**，不是在人家的框架里改业务逻辑
- 「独立」意味着：不用别人先把框架搭好，一个人能从零跑通
- 面试加分项：能讲清内部的**状态机是怎么设计的**

### 3. 根据大模型效果进行优化

- **先有评测，再谈优化**。没有评测集的「优化」就是瞎调
- 「优化」的主体是**整个 Agent 系统**，微调只是最后才动的手段之一

> 岗位日常其实包含：搭骨架、写与迭代 prompt、接工具、做评测优化、工程化（并发/缓存/成本/日志/异常/部署）、与产品对接。
> **能搭起来只是入场券，能持续优化才是价值所在。**

## 错误归因表

> 核心方法论：**先有评测 → 再看 bad case → 归因 → 对症下药。**
> 不同病用不同药，**乱吃药比不吃更糟**。

| 症状 | 可能的病因 | 处方 |
| --- | --- | --- |
| 答错 / 不知道 | 模型缺乏这部分知识 | 加 RAG → 仍不行再考虑微调 |
| 答对但格式乱 | 输出约束不明确 | 改 prompt、加 JSON Schema、加校验重试 |
| 选错工具 / 参数错 | 工具描述不清晰 | 改工具名与 description、精简工具数量 |
| 信息明明给了却答错 | 上下文被淹没 | 上下文管理：裁剪、摘要、重排序 |
| 死循环 / 跑不完 | 缺终止条件 | 加最大步数、超时、循环检测 |
| 效果还行但太贵 | 模型过大 / 上下文太长 | 换小模型、缓存、精简上下文、蒸馏 |

# 附录：名词速查

| 名词 | 含义 |
| --- | --- |
| **LLM** | Large Language Model，大语言模型 |
| **NLP** | Natural Language Processing，自然语言处理 |
| **PE** | Prompt Engineering，提示词工程 |
| **Agent** | 让模型自主决策下一步的系统（LLM + 工具 + 记忆 + 循环） |
| **Function Calling** | 让模型输出结构化「调用意图」，由程序执行，使模型能操作外部世界 |
| **ReAct** | Reason + Act，Agent 的经典范式（思考→行动→观察） |
| **RAG** | Retrieval-Augmented Generation，检索增强生成：把外部知识检索回来注入上下文 |
| **SFT** | Supervised Fine-Tuning，监督微调：用标注数据训练模型听指令 |
| **LoRA** | 低秩适配，一种轻量微调方法，只训练少量参数 |
| **蒸馏** | Distillation，用大模型的输出训练小模型 —— 属**成本优化** |
| **MCP** | Model Context Protocol，标准化的工具 / 上下文接入协议 |
| **MoE** | Mixture of Experts，混合专家：稀疏激活，小算力大参数 |
| **RNN / LSTM** | 循环神经网络 / 长短期记忆网络，Transformer 之前的序列建模主力 |
| **HMM / CRF** | 隐马尔可夫模型 / 条件随机场，序列标注的经典生成式 / 判别式方法 |
